## Section 4 — RPC Authorization Tests

Run in Supabase SQL Editor as each role's user. Replace `<user_jwt>` with a valid JWT for that role.

```sql
-- ── TEST SETUP ───────────────────────────────────────────────────────────────
-- For each test, set the session role:
-- SELECT set_config('request.jwt.claims', '{"sub":"<user_uuid>","role":"authenticated"}', true);

-- ── 4.1 get_admin_role() ─────────────────────────────────────────────────────
-- Expected: returns role TEXT for any admin user, NULL/error for non-admin
SELECT get_admin_role();
-- super_admin   → 'super_admin'
-- sales_agent   → 'sales_agent'
-- viewer        → 'viewer'
-- anon          → NULL or error (SECURITY DEFINER checks admin_users)

-- ── 4.2 get_my_permissions() ─────────────────────────────────────────────────
-- Expected: returns JSON with role + permissions array
SELECT get_my_permissions();
-- viewer: permissions should be [] (empty)

-- sales_agent: should NOT include approve_expenses, write_invoices

-- ── 4.3 has_permission('manage_admins') ──────────────────────────────────────
-- Expected: true only for super_admin
SELECT has_permission('manage_admins');
-- super_admin   → true
-- admin         → false  ← CRITICAL: admin must NOT manage admins
-- sales_agent   → false
-- viewer        → false

-- ── 4.4 has_permission('approve_expenses') ───────────────────────────────────
SELECT has_permission('approve_expenses');
```

## Section 5 — RLS Verification Tests

```sql
-- ── 5.1 Leads table: sales_agent A cannot see sales_agent B's leads ───────────
-- As sales_agent A (user_A_uuid):
SELECT id, assigned_to FROM leads WHERE assigned_to != auth.uid();
-- Expected: 0 rows (RLS policy: assigned_to = auth.uid() OR manager role)

-- ── 5.2 Accounting audit logs: no INSERT for regular users ───────────────────
-- As accountant:
INSERT INTO accounting_audit_logs (action, entity_type) VALUES ('test', 'test');
-- Expected: ERROR (no INSERT policy; only triggers write to this table)

-- ── 5.3 admin_users: viewer cannot read other users ──────────────────────────
-- As viewer:
SELECT id, email, role FROM admin_users;
-- Expected: 0 rows or own row only (RLS)

-- ── 5.4 journal_entries: cashier cannot read ─────────────────────────────────
-- As cashier:
SELECT id FROM journal_entries LIMIT 1;
-- Expected: 0 rows (cashier has read_cash_bank but not read_journal)

-- ── 5.5 nsp_expenses: viewer cannot INSERT ───────────────────────────────────
-- As viewer:
INSERT INTO nsp_expenses (total_amount, status) VALUES (100, 'draft');
-- Expected: ERROR (RLS: can_write_financial() required)

-- ── 5.6 Posted expense: cannot be edited even by financial_manager ────────────
-- As financial_manager (trigger guard):
UPDATE nsp_expenses SET total_amount = 999 WHERE status = 'posted' LIMIT 1;
-- Expected: ERROR from trg_guard_expense

-- ── 5.7 Closed fiscal period: journal entries blocked ────────────────────────
-- As super_admin, try to post to a closed period:
UPDATE journal_entries SET status = 'posted'
WHERE fiscal_period_id = (SELECT id FROM fiscal_periods WHERE status = 'closed' LIMIT 1);
-- Expected: ERROR from trg_fp_enforce

-- ── 5.8 B2B partner portal: partner sees only own data ───────────────────────
-- As partner_user (partner A):
SELECT id FROM partner_inquiries WHERE partner_id != (SELECT id FROM b2b_partners WHERE id IN (
  SELECT partner_id FROM partner_portal_users WHERE user_id = auth.uid()
));
-- Expected: 0 rows
```

## Section 7 — Critical Security Invariants

These must ALWAYS hold regardless of role:

```
[ ] 1. Unauthenticated request to any admin page → redirect to login
[ ] 2. viewer cannot INSERT/UPDATE/DELETE any business record
[ ] 3. cashier cannot read journal_entries
[ ] 4. accountant cannot approve_expenses (only record them)
[ ] 5. admin cannot manage_admins or manage_users (super_admin only)
[ ] 6. sales_agent cannot read financial records (invoices, journal, payments)
[ ] 7. Posted expenses cannot be edited by anyone (trigger guard)
[ ] 8. Closed fiscal periods block new journal postings (trigger guard)
[ ] 9. accounting_audit_logs: no user can INSERT directly (triggers only)
[ ] 10. Partner portal users see only own partner's data
[ ] 11. Anon/unauthenticated cannot call any admin RPC
[ ] 12. get_my_permissions() for viewer returns empty array []
```
